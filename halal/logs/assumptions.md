# What v22 assumes about the world, and whether it holds out there (red-team, 14.11 night)

Analysis only: no code, config or branch changed. Code read: v22 tree (`cae48ed`; main `22c971d` differs only in logs and a config
comment). Method: I walked `server.py` -> `SortPolicy.act/reset` -> looking -> `TopFaceDetector.detect` -> calibration / hands / bins /
colour / shapes -> `PickChooser` -> `PickPlanner` -> organiser `Planner` / `SafetyFilter` -> runner and backends, and wrote down each
world fact the code relies on. Only then did I check each one against the organiser docs, `scene.yaml`, `calibration.yaml`,
`realdata.md`, `robot.md`, the organisers' notes on tonight's runs and the other logs.
Evidence keys: **R** = tonight's robot runs (`robot.md`, organisers' notes), **D** = real drops (`realdata.md`), **S** = sim-only.
"Fails safe" means objects are left on the counter (0 points). "Fails bad" means wrong bin, knocked off, or the robot frozen or aborted.
